# 风格建模与声音校准

风格学习不是模仿一个人的履历、观点和私人经历，而是从同一作者的样本中提取可证据化的表达选择。样本之外的事实、立场、故事和口头禅不能被带进新稿。

## 两层声音档案

参考 Ghostwriter 的“核心声音 + 场景声音”分法，但不要求安装外部 Skill：

- **核心声音**：跨公众号、报告、邮件、口播都相对稳定的取舍，例如作者与读者的距离、判断强度、常用动词、结尾方式和不愿使用的表达。
- **场景声音**：只在某类交付物成立的表达，例如公众号允许的段落松紧、管理层通报的责任语气、视频口播的停顿或技术文档的命令式清晰度。

核心声音不能覆盖正式文种和专业验收；场景声音不能反向改写事实。先建立档案，再写新稿；不要在最后去 AI 味阶段才临时发明一个“像本人”的人格。

## 样本门

- 最好有 3–5 篇同体裁、近期、确认属于同一作者的样本。
- 多作者样本先按作者锚点分组。作者不明或混合样本不能直接生成稳定风格档案。
- URL 先提取正文并保存本地副本，再分析纯文本；不要把 URL、标题或网页摘要当作样本。
- 一篇样本只能产生候选特征。稳定规则至少需要两篇独立样本支持。
- 用户自己的样本优先于公开印象；只学习表达方式，不复制原句和私人信息。

## 证据账本

每条风格判断都记录：

| 字段 | 要求 |
| --- | --- |
| 观察 | 样本里实际出现的句式、取材或节奏 |
| 短摘录 | 只保留证明判断所需的最短片段 |
| 位置 | 文件、标题、段落或 URL |
| 功能 | 该写法在当时解决了什么沟通问题 |
| 可复用规则 | 换到新主题时如何复现 |
| 边界 | 什么场景不能用 |
| 置信度 | high、medium 或 candidate |

## 15 个观察维度

1. 作者与读者关系；
2. 选题切入和开头；
3. 核心判断与论证顺序；
4. 素材选择与拒绝项；
5. 现象到机制的推进；
6. 例子、类比和具体化方式；
7. 段落过渡；
8. 句长、分句和停顿；
9. 词汇、动词和程度词；
10. 设问、反问、对比和排比的功能；
11. 情绪、幽默和确定性表达；
12. 第一人称、第二人称和群体称呼；
13. 小标题、列表、加粗和引用格式；
14. 结尾、留白和行动落点；
15. 反模式、禁用表达和适用边界。

先把“任何好作者都会做”的规则归为通用基线，再保留真正能区分作者的特征。不要把“观点明确、事实具体、少说废话”冒充个人风格。

## 量化与验证

可以运行仓库内的 `check_writing.py --json`，观察句长分布、词汇重复、段落结构和模式命中，但中文统计只作辅助信号。句长变化不能证明某个人的风格，词汇多样性也不能证明文本来自人类。

用一个样本没有覆盖的新主题做 300–500 字验证，按以下维度各 0–2 分：切入角度、素材取舍、论证推进、句式节奏、读者关系。每个高分都要能回指账本。总分低于 8 分，降低风格规则或补样本。

条件允许时做 3 组盲测：每组放一段原文和一段仿写，随机打乱，不告诉评审作者和风格文件。允许“无法判断”，只记录判断、置信度和可观察证据。评审结果不是文学权威，只用于发现风格规则过宽或过拟合。

## 输出边界

- 样本不足时输出“低置信度声音校准”，不假装完成作者画像。
- 新稿的事实、数字、人物经历和行业判断来自新稿材料，不从样本偷渡。
- 专业、党政、安全和技术文档的格式和准确性高于风格模仿。
- 用户只说“自然一点”时不自动进入风格学习；默认走事实优先的通用声音。
- 作者人工终审后的反复修改，才是声音档案的高价值反馈；单篇偶然改动先留在终审记录。
