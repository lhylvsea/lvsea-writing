# Plain writing 适配说明

本文件记录 `lvsea-writing` 对 [docwriter-org/plain-writing-skill](https://github.com/docwriter-org/plain-writing-skill) 的按需吸收。审阅版本为主分支提交 `f0d3630983ac7a82aa580f1c1509d72df739ee12`，审阅日期为 2026-10-14，上游许可证为 MIT。

这里只吸收普通语言、清楚结构和 `deslopify` 的工作方式，不复制上游 `SKILL.md`、评测数据、历史记录或结果表。`plain-writing` 在本包中是一个可选的清楚表达层，不是覆盖所有体裁的总风格。

## 取舍

| 决定 | 吸收或排除的内容 |
| --- | --- |
| 保留 | 简单常用词、必要术语先定义、主语和动作明确、术语前后一致、删空泛强调、先结论后背景、按顺序说明、段落先主旨后支撑、减少假拟人、连续设问和口号式表达 |
| 改造 | 英文规则改成中文语境下的编辑检查；“plain/boring”改成清楚、克制、易读；保留制造、技术、政策和口播所需的专业术语与格式；把上游 `deslopify` 变成 `$lvsea-writing` 的兼容模式 |
| 不采用 | 对所有文本强制长句、禁止一切破折号或比喻、禁止缩写和必要术语、把 Merriam-Webster 词典当作中文门槛、把 67 个外部评测任务或数据集打包进本仓库 |
| 新增 | `plain/deslopify` 模式、按需的 `revision-view.md` 修改对照、清楚表达与作者声音和正式文种之间的冲突处理规则 |

## 适用边界

适合在以下请求中启用：

- 用户说“通俗一点、简洁明白、去掉废话、让没有上下文的人一遍看懂”；
- 用户要求 `plain`、`deslopify` 或兼容 `/plain-writing deslopify` 的写法；
- 项目更新、README、PR 说明、管理层简报、技术说明和政策解读需要减少术语堆叠时；
- 用户明确要求“告诉我改了什么”，需要一份可复核的修改对照时。

不适合把它当作默认覆盖层的场景包括：文学性创作、需要保留作者口语和隐喻的个人文字、广告口号、诗歌、逐字引语、法律或政策原文、代码本身以及用户明确要求保留的格式。遇到这些场景，先服从体裁、来源和作者要求。

## Plain 模式流程

```text
确认读者和用途 -> 先写主结论 -> 补背景和必要术语
-> 说明动作、条件和结果 -> 删除空泛表达
-> 保留事实、格式和声音 -> 事实回查
```

执行时按以下顺序处理：

1. 先确认读者是否缺少项目背景，以及读者需要据此做什么。
2. 把主结论或当前状态放在前面，再补必要背景，不用口号或悬念拖延进入主题。
3. 优先用普通词。必须保留的技术、工艺、政策和产品术语不删除；读者可能不熟悉时，第一次出现就用一句话解释。
4. 检查主语、动作、对象、条件和结果。不要把数据、市场、算法或系统写成有意图的人，也不要用“这说明”“那个问题”掩盖具体对象。
5. 删除没有增加事实、判断、行动或情绪的强调词、宣传词、口号、连续设问、翻案套句和自造复合形容词。发现真实的比喻有解释作用时可以保留，不为规则而删。
6. 让段落先说主旨，再给事实或例子。复杂过程按实际顺序写，不能为了短而删掉条件、限制或责任边界。
7. 逐项回查数字、名称、日期、链接、引语归属、技术术语、Markdown 结构和作者明确要求保留的表达。

中文写作不机械照搬上游英文的句长、破折号、引号或词典规则。平实表达的目标是降低理解成本，不是把所有文字压成同一种节奏。

## 修改对照

用户明确要求“显示修改了什么、给修改对照或保留修改理由”时，提供可选的 `revision-view.md`，内容至少包括：

- 目标读者、体裁和本轮编辑范围；
- 删除或改写的空话、术语、句式和结构问题；
- 保留的数字、名称、引用、条件、责任边界和专业术语；
- 仍需作者确认的事实、语气或格式；
- 未改动的部分及原因，避免让作者误以为全文被重写。

用户说“只返回改写后的正文”时，不输出修改说明。修改对照不能把内部提示词、隐藏推理或未经核实的评分写进正文。

## 与主流程的关系

`plain/deslopify` 可以在短改稿中作为主要编辑模式，也可以在完整初稿后作为一次清楚表达复查。它不能替代资料、证据账本、主判断、读者测试、专业核验、最后 Humanizer 或作者人工终审。需要去 AI 味时，仍按 `lvsea-writing` 的顺序把最终 Humanizer 放在后面；Plain 模式只负责让意思更清楚，不负责证明文本来自谁。

## 证据边界

上游仓库的外部评测结果只说明它在指定模型和任务上的评测表现，本包没有复跑，也不把这些数字转成中文写作质量承诺。本包只吸收规则和输出合同，并通过本仓库的触发评测、包校验和人工边界审查验证结构是否一致。
